# Connect — Runbook (operating the pilot)

How to deploy, run and repair Connect. ROADMAP T10.2–T10.5 · Decisions: ADR-029, ADR-031.
Secrets are **never** in git: locally they live in `backend/.env.supabase` (git-ignored); in production in Render's environment settings.

## 1. What runs where (all free tiers)

| Piece | Service | Notes / limits |
|---|---|---|
| API | Render free web service `connect-api` (Singapore) — `render.yaml` | Sleeps after ~15 min idle; first request then takes up to ~1 min. 750 h/month |
| Database | Supabase project `neoijibrnmnxloymnwjs` (Postgres 17, ap-southeast-1) | 500 MB. No downloadable backups on free → §6 |
| Photos | Supabase Storage bucket `media` (public read, 5 MB, jpeg/png/webp) | 1 GB |
| Email | Brevo free | 300 emails/day. Sender address must be verified in Brevo |
| Payments | Razorpay **test mode** | Only `rzp_test_` keys are accepted — no real money (ADR-004) |
| App for testers | EAS Build (Expo) → Android APK | Free build queue can take a while |
| Push | Expo push service | Works only in real builds (not Expo Go) |

### Database connection strings (Supabase → Connect)
| Use | String | Why |
|---|---|---|
| API runtime `DATABASE_URL` | **Transaction pooler** `…pooler.supabase.com:6543` | IPv4 (Render has no IPv6); many short connections |
| Migrations `DIRECT_URL` | **Session pooler** `…pooler.supabase.com:5432` (or the direct host from an IPv6 network) | Migrations need a session |
| TLS | `DATABASE_CA_CERT_PATH=certs/supabase-prod-ca-2021.crt` | Certificate is verified (ADR-031) |

Passwords containing special characters must be URL-encoded inside these strings (`@` → `%40`).

## 2. First deploy of the API (Render)
1. Render → **New → Blueprint** → connect GitHub → repo `CampusConnect-MVP` → it reads `render.yaml`.
2. Fill the values Render asks for (`sync: false`):
   - `DATABASE_URL` = transaction pooler string · `DIRECT_URL` = session pooler string
   - `BREVO_API_KEY`, `MAIL_FROM_EMAIL` (the Brevo-verified sender)
   - `SUPABASE_SERVICE_ROLE_KEY` (Supabase → Project Settings → API keys; server-side only)
   - `RAZORPAY_KEY_ID` (`rzp_test_…`), `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`
   - `PUBLIC_API_URL` = `https://connect-api.onrender.com` (or the URL Render shows)
   `JWT_ACCESS_SECRET` and `CODE_HASH_SECRET` are generated by Render — nobody needs to see them.
3. **Manual Deploy** (auto-deploy is off on purpose). Wait for "Live".
4. Check: open `https://<your-service>.onrender.com/api/v1/health` → `{"status":"ok","database":"up"}`.
   If it fails, Render → Logs: the API prints exactly which setting is missing or wrong (never the value).
5. Razorpay (test mode) → Settings → Webhooks → URL `https://<your-service>.onrender.com/api/v1/webhooks/razorpay`, events `payment.captured`, secret = `RAZORPAY_WEBHOOK_SECRET`.
6. If the service URL is not `connect-api.onrender.com`, change `EXPO_PUBLIC_API_URL` in `mobile/eas.json` before building the app.

The build was rehearsed locally on a clean clone (exact build command, then a production-mode start against Supabase → health OK) on 2026-11-19.

## 3. Android app for testers (EAS)
```bash
cd mobile
npx eas-cli@latest login          # free Expo account
npx eas-cli@latest init           # once: links the project (adds the project id to app.json — commit it)
npx eas-cli@latest build -p android --profile preview
```
EAS prints a link/QR code to install the APK. Testers allow "install unknown apps" once. The app talks to the API URL in `eas.json` (`preview` profile). App id: `app.connect.india` (can be changed until the first Play Store upload).

## 4. Database migrations (deliberate, never automatic)
Migrations are **not** run on deploy. Every migration is reviewed first; destructive ones need founder approval.
```powershell
cd backend
# 1. create: edit prisma/schema.prisma, then generate SQL against your local dev database
npx prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script -o prisma/migrations/<timestamp>_<name>/migration.sql
# 2. review the SQL (additive? data loss?), run tests, commit
# 3. back up production (§6), then apply to Supabase:
Get-Content .env.supabase | Where-Object { $_ -match '^(DIRECT_URL|DATABASE_CA_CERT_PATH)=' } | ForEach-Object { $k,$v = $_ -split '=',2; Set-Item "Env:$k" $v }
npx prisma migrate deploy
Remove-Item Env:DIRECT_URL, Env:DATABASE_CA_CERT_PATH
```
Rule for new tables: also `ALTER TABLE … ENABLE ROW LEVEL SECURITY` (ADR-029) — `test/schema-safety.e2e-spec.ts` fails otherwise.

## 5. Day-to-day admin
- Make someone admin: set `DIRECT_URL` + `DATABASE_CA_CERT_PATH` as in §4, then `npm run admin:grant -w @cc/backend -- person@example.com` (`--revoke` to undo).
- Reports, suspensions, disputes, auto-approve, ledger check: API calls in `backend/src/modules/admin/README.md`. Check `GET /admin/ledger/reconcile` weekly → `ok: true`.
- Disputes: read the order timeline and chat, decide REFUND or RELEASE, always write a note.

## 6. Backups and restore
Take a backup at least weekly and **before every migration**:
```powershell
cd backend
$env:BACKUP_DATABASE_URL = ((Get-Content .env.supabase | Select-String '^SESSION_POOLER_URL=') -replace '^SESSION_POOLER_URL=','')
npm run db:backup
Remove-Item Env:BACKUP_DATABASE_URL
```
It dumps the database (inside the local Docker Postgres 17 container — needs `npm run db:up`), saves `backups/connect-<time>.dump` (git-ignored; contains user data — keep it private, e.g. an encrypted drive), then **restores it into a throwaway local database and compares every table's row count** (tested 2026-11-19: Supabase 27 tables/49 rows, load database 20,468 rows — identical).

**Restore into a new Supabase project** (disaster): create the project → apply migrations (§4) with the new `DIRECT_URL` → restore data only:
```bash
docker cp backups/<file>.dump campusconnect-postgres:/tmp/r.dump
docker exec -e PGPASSWORD=<password> -e PGSSLMODE=require campusconnect-postgres pg_restore --data-only --no-owner --no-privileges --disable-triggers -d "<new session pooler URL without password>" /tmp/r.dump
```
then update `DATABASE_URL`/`DIRECT_URL` in Render and redeploy.

## 7. Rotating secrets
| Secret | How | Effect |
|---|---|---|
| Supabase DB password | Supabase → Database → reset password → update `DATABASE_URL`, `DIRECT_URL` in Render and `.env.supabase` → redeploy | None for users. **Do this before real users (the current one was shared in chat).** |
| `JWT_ACCESS_SECRET` | Render → regenerate → redeploy | Everyone's access token stops working; apps refresh silently |
| `CODE_HASH_SECRET` | Render → regenerate → redeploy | Pending email codes stop working (users request a new one) |
| Brevo key / service-role key / Razorpay keys | Create new in the provider → update Render → redeploy → delete old | None |

## 8. When something breaks
| Symptom | Check |
|---|---|
| App says "Can't reach Connect" | Health URL. Free service may be waking up (wait 1 min). Render → Logs |
| Health shows `database: down` | Supabase status page; pooler string/password in Render; project paused after inactivity? (free projects pause after ~1 week idle — Supabase → Restore) |
| No verification emails | Brevo → Transactional → Logs; daily 300 limit; sender still verified; spam folder |
| Photos fail to upload | `SUPABASE_SERVICE_ROLE_KEY` set? bucket `media` exists (5 MB, image types) |
| Wallet top-up stuck | Razorpay test dashboard → payment status; webhook URL/secret; the app's "I've paid — check now" re-checks with Razorpay |
| Money looks wrong | `GET /admin/ledger/reconcile`; do not edit money rows by hand |
